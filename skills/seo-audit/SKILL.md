# SEO audit

Review the requested site or routes for concrete issues that prevent search engines and visitors from understanding and reaching useful content. Focus on evidence in the source, rendered pages, and available first-party search data.

## Scope and inspect

- Identify the site type, important pages, target markets/languages, rendering approach, and available analytics or search-console data. State assumptions when these are not provided.
- Check indexability controls: status codes, robots directives, canonical URLs, redirects, sitemap, robots.txt, internal links, and client-side rendering of essential content.
- Review page titles, descriptions, headings, language/locale signals, duplicate or thin content, image alternatives, and descriptive link text.
- Validate structured data against the visible page content and the relevant schema format. Flag invalid or misleading markup; do not add review, product, organization, or other claims that the page does not substantiate.
- Consider mobile rendering, performance, accessibility, and security where they materially affect discovery or usability, while keeping those specialist reviews in scope only as needed.
- Use first-party data when available. Browse official search documentation only when current platform requirements materially affect the recommendation.

## Prioritize

- Tie each finding to an affected URL or template, evidence, likely effect, and a specific correction.
- Fix crawl/indexing blockers and broken canonical/redirect behavior before low-impact copy refinements.
- Separate technical issues, content opportunities, and speculative ranking hypotheses. Do not promise ranking position, indexing time, or traffic growth.
- Make changes only within the user's requested scope. Preserve accurate content and existing URL equity; do not delete or rewrite pages broadly without clear direction.

## Report

Summarize the routes and data reviewed, prioritized findings, changes made if requested, and limits such as unavailable search data or inaccessible pages. Distinguish directly observed issues from recommendations that need validation after deployment.
